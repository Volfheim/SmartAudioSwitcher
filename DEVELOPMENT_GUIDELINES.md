# Руководство по разработке и релизам (Development Guidelines)

Этот файл содержит ключевые правила и инструкции для ИИ-агента, работающего над проектом SmartAudioSwitcher. Обязательно сверяйтесь с этим файлом перед внесением изменений и созданием новых релизов.

## 1. Управление версиями (Version Bumping)
При каждом новом релизе необходимо **обязательно** обновлять версию программы в файле `SmartAudioSwitcher\SmartAudioSwitcher.csproj`.
Нужно обновить **сразу три** параметра, чтобы скомпилированный бинарный файл правильно распознавал свою версию:
```xml
<Version>X.Y.Z</Version>
<AssemblyVersion>X.Y.Z</AssemblyVersion>
<FileVersion>X.Y.Z</FileVersion>
```

## 2. Сборка проекта (Build Process)
Компиляция проекта должна происходить **строго из папки проекта**, а не из корневой папки решения, чтобы избежать ошибки `NETSDK1194` и несогласованности путей.
```bash
# Правильный процесс сборки:
cd SmartAudioSwitcher
dotnet publish -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=false -o bin\Publish\Light_SingleFile
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o bin\Publish\Full_SelfContained
cd ..
```
Сборка всегда должна включать две версии: `Light_SingleFile` (зависит от установленного .NET) и `Full_SelfContained` (независимая, больше по размеру). Архивация (создание .zip) для Full версии **не требуется**, отправляем просто .exe файл.

## 3. Оформление релизов (GitHub Releases)
- **Название релиза:** Название релиза на GitHub должно быть строго `SmartAudioSwitcher` (без указания версии вроде v3.0.0, так как версия и так отображается в теге).
- **Описание релиза:** Описание (Release notes) должно быть **на английском языке**.
- **Теги:** Тег должен быть в формате `vX.Y.Z`.
- Обязательно прикреплять к релизу оба скомпилированных файла (`SmartAudioSwitcher.exe` и `SmartAudioSwitcher_Full.exe`).

## 4. Автоматизация релизов и GitHub Token
Для публикации релизов через GitHub REST API используется специальный Python скрипт (например, `release_vX.Y.Z.py`).
Для авторизации API у нас есть **уже работающий классический токен (Classic PAT)**.

**КРИТИЧЕСКИ ВАЖНО:** Этот токен имеет полные права на управление репозиторием. **Никогда не хардкодьте его в текст скрипта и не отправляйте (git push) в публичный репозиторий!** Если GitHub обнаружит его в коммите, токен будет немедленно и навсегда отозван (Revoked).
Используйте его исключительно как переменную окружения:
```bash
$env:GITHUB_TOKEN="ваш_токен_здесь"
python release_vX.Y.Z.py
```

## 5. Общение и стиль кода
- ИИ-агент должен общаться с пользователем **только на русском языке**.
- Коммиты от лица ИИ должны быть написаны от первого лица (например, *"В этой версии я сделал..."*).
- При написании кода соблюдать баланс (никаких лишних хаков, не усложнять без необходимости, придерживаться DRY), всегда обсуждать архитектуру и предлагать рекомендации перед внесением изменений.
